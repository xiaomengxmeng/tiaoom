| 万物亲和 | `NATURE_BOND` | 君 | 第一名↔最后一名牵引线，互撞伤害-15%，移速+10% |

## 2. 已发现 Bug（需修复）

### 🔴 Bug 1: 万物亲和 - 速度无限膨胀

**严重程度**: 致命（物理引擎崩溃）

**位置**: `FishOilRoom.ts` battleTickLoop 3.5节

```typescript
// 每 tick (50ms) 都会执行
for (const ball of this.physics.getAllBalls()) {
  const newSpeed = this.globalEffectSystem.modifySpeed(ball.id, ball.speed);
  // NatureBond.modifySpeed 永远返回 currentSpeed * 1.10
  if (newSpeed !== ball.speed) {
    this.physics.modifyBallSpeed(ball.id, newSpeed);
  }
}
```

**问题**: `modifySpeed` 每 tick 乘以 1.10，速度指数级增长：

| tick | 速度 | 时间 |
|:---|:---|:---|
| 0 | 200 | 0s |
| 1 | 220 | 0.05s |
| 2 | 242 | 0.1s |
| 20 | ~1345 | 1s |
| 200 | ~3.8×10¹⁰ | 10s |

**根因**: 修改的是"当前速度"而非"基础速度"，缺少参照基准。

**修复方案 A（推荐）**: 在 `onBattleStart` 时记录每个球的"基准速度"，modifySpeed 始终基于基准速度计算：

```typescript
class NatureBondEffect implements IGlobalEffect {
  private baseSpeeds = new Map<string, number>(); // 记录基准速度

  onBattleStart(state: IBattleState, physics: PhysicsEngine): void {
    this.baseSpeeds.clear();
    for (const ball of physics.getAllBalls()) {
      this.baseSpeeds.set(ball.id, ball.speed);
    }
  }

  modifySpeed(playerId: string, _currentSpeed: number): number {
    const base = this.baseSpeeds.get(playerId);
    if (base === undefined) return _currentSpeed;
    return base * NatureBondEffect.SPEED_MULTIPLIER; // 始终 1.10 × 基准
  }
}
```

**修复方案 B**: 移除每 tick 的 modifySpeed 调用，改为在 `onBattleStart` 一次性应用：

```typescript
onBattleStart(state: IBattleState, physics: PhysicsEngine): void {
  for (const ball of physics.getAllBalls()) {
    physics.modifyBallSpeed(ball.id, ball.speed * NatureBondEffect.SPEED_MULTIPLIER);
  }
}
```

方案 A 更好，因为它允许后续动态开关效果。

### 🔴 Bug 2: 古今观察者 - 复活与 deadPlayers 冲突

**严重程度**: 致命（复活瞬死）

**位置**: `FishOilRoom.ts` battleTickLoop 第 5 步（行 596-604）vs GlobalEffectSystem 回溯逻辑（行 176-185）

**问题链**:
1. 玩家死亡 → 加入 `deadPlayers` → `physics.removeBall(id)`
2. 古今观察者回溯 → 恢复玩家 HP > 0 → `physics.addBall(id, ...)` ✅
3. **但未从 `deadPlayers` 中移除玩家** ❌
4. 下一帧 battleTickLoop 第 5 步检查：`pstate.hp > 0` 但 `deadPlayers.has(pid)` 为 `false`（因为已经加入了）... 

等等，让我重新分析。死亡检查的条件是 `pstate.hp <= 0 && !this.deadPlayers.has(pid)`。回溯后 hp > 0，所以第一个条件不满足，不会被重新标记死亡。

但问题是：**playerDeathTime 仍保留着旧的死亡时间戳**，可能影响结算逻辑。

**实际上真正的冲突是**:
- 回溯后物理引擎中的球是 `addBall` 新加的，没有速度（vx=0, vy=0），球会静止
- `playerDeathTime` 和可能的其他死亡状态残留

**修复方案**:
```typescript
// 在 TimeObserverEffect.triggerRevert() 中，复活玩家后：
if (pastState.hp > 0 && wasDead) {
  // 需要通知 FishOilRoom 清理死亡状态
  // 方式1: 提供回调
  // 方式2: 通过 state 标记
  player.isDead = false; // 如果 IBattleState 支持
}
```

**以及**，在 `FishOilRoom` 中需要暴露清理方法：
```typescript
clearDeadPlayer(playerId: string): void {
  this.deadPlayers.delete(playerId);
  this.playerDeathTime.delete(playerId);
}
```

需要给 `TimeObserverEffect` 注入这个回调。

2. 暴露 `activeGlobalEffect` 到 UI state

// useFishOilBattle.ts
const activeGlobalEffect = ref<{ type: string; name: string } | null>(null);

socket.on('global_effect_activated', (data: { effectType: string; effectName: string }) => {
  activeGlobalEffect.value = { type: data.effectType, name: data.effectName };

## 3. 架构改进建议

### 3.1 速度管理

目前 `modifySpeed` 没有区分"临时扰动"和"常驻光环"，建议增加语义：

```typescript
interface IGlobalEffect {
  /** 常驻速度修正（光环类，基于基准速度，不叠加） */
  getSpeedMultiplier?(playerId: string): number;
  /** 一次性速度扰动（事件类，立即生效，不持续） */
  onSpeedPerturbation?(tick: number, physics: PhysicsEngine): void;
}
```

### 3.2 死亡状态管理

`deadPlayers` 当前是 `FishOilRoom` 的私有集合，全局效果需要修改它。建议：
- 将死亡状态移到 `IBattleState` 中
- 或者给 `GlobalEffectSystem` 提供 `onPlayerResurrected` 回调

### 3.3 前端彩蛋 UI

建议在 HUD 或战斗画布角落添加彩蛋指示器：
- 显示当前激活的彩蛋名称和图标
- 古今观察者：倒计时条（15s→0）
- 俺寻思之力：下次扰动倒计时
- 万物亲和：牵引线距离提示
